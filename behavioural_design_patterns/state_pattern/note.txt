The State Design Pattern is a behavioral software design pattern that allows an object to alter its behavior when its internal state changes. To the outside observer, the object appears to change its entire class at runtime.

• An object's behavior changes dynamically based on its current properties/status.
• Your methods are becoming polluted with heavy, duplicate conditional checks evaluating a status flag.
• You need to adhere to the Open/Closed Principle, meaning you want to add new states in the future without modifying existing state code.

Changes can be explicit or in response to an event
A formalized construc that manages state and transition is called a state machine
